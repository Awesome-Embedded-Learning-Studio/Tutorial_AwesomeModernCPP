# 从配置到翻转：四位户口与原子置位

电送上了（时钟合闸），路修通了（MMIO），今天的活儿是两个动作：**给引脚上户口**（配置模式），**让引脚翻身**（输出翻转）。做完这两个动作，裸寄存器点灯的全程就闭环了——从此您看任何外设库的 GPIO 代码，眼底都是地址和位。

## 户口本：每个引脚四位

一个 GPIO 端口十六条脚，配置寄存器却只有一对：`CRL` 管 pin0-7，`CRH` 管 pin8-15。每个脚分到四位：低两位 `MODE[1:0]`，高两位 `CNF[1:0]`。PC13 是高半段的第五位住户，偏移一道算术：`(13 - 8) × 4 = 20`，所以它的四位住在 CRH 的 bit23-20。设备头文件里的宏就是这么写的（`stm32f103xb.h` L1576-L1632）：

```cpp
#define GPIO_CRH_MODE13_Pos   (20U)
#define GPIO_CRH_MODE13_Msk   (0x3UL << GPIO_CRH_MODE13_Pos)   // 0x00300000
#define GPIO_CRH_CNF13_Pos    (22U)
#define GPIO_CRH_CNF13_Msk    (0x3UL << GPIO_CRH_CNF13_Pos)    // 0x00C00000
```

四位一共十六种组合，常用的八种列成表（完整表在 RM0008 第 9 章，这张是手册的翻译）：

| MODE | CNF | 意思 | 典型用途 |
|------|-----|------|---------|
| 00 | 00 | 模拟输入 | ADC 采样 |
| 00 | 01 | 浮空输入 | 复位默认；外部信号电平稳定时 |
| 00 | 10 | 上拉/下拉输入 | 按键（F1 里上拉还是下拉由 ODR 决定，第八篇见） |
| 01 | — | 10MHz 输出 | 中速驱动 |
| 10 | 00 | 2MHz 推挽输出 | 咱们点灯的选择 |
| 10 | 01 | 2MHz 开漏输出 | I2C 这类总线（第五站见） |
| 11 | 00 | 50MHz 推挽输出 | 高速驱动 |
| 1x | 1x | 复用输出 | 片上外设接管引脚时 |

咱们要 PC13 当一个普通 2MHz 推挽输出脚：`CNF=00, MODE=10`，四位合起来 `0010`，落到位上就是 `0x2 << 20 = 0x00200000`。对着上一篇 Renode 读回的 `CRH = 0x00200000`，逐位对上，一个位都不差。

复位默认值也值得看一眼。手册说 CRL/CRH 复位后是 `0x44444444`——每个脚 `0x4`，即 `CNF=01, MODE=00`：浮空输入。上电之后所有脚先当"只读的耳朵"，等您来上户口。（Renode 的模型口径又和手册岔了一道：它给的复位值是 `0x00000000`。咱们在模拟器里读复位值时读到的是 0，上一篇的门控偏差是"模型少算了约束"，这道是"模型没按手册设默认值"——同一个药方：**逻辑看模型，默认值与时序看手册**。）

于是配置这两行的意思完全透明了：

```cpp
GPIOC->CRH &= ~(0xFu << 20);   // 清掉 PC13 的四位旧户口
GPIOC->CRH |=  (0x2u << 20);   // 写入新户口: 0010 = 2MHz 推挽输出
```

上一篇的反汇编已经给这两行验过身：`bic.w` 清位、`orr.w` 置位，前后两次读改写，落进 `0x40011004`。

## 翻车实录：写错半段的代价

这份例程的第一版，笔者亲手翻过一次车，注释原文还留在 `main.cpp` 里（L36-L39）：

```cpp
// 2) PC13 模式:pin ≥ 8 的配置段住在 CRH(每脚 4 位:pin13 → 偏移
//    (13-8)*4=20,CNF 占 bit23:22,MODE 占 bit21:20)。第一版把这段写进
//    CRL(配成了 pin5),PC13 保持复位默认的浮空输入,BSRR/BRR 写了
//    也不驱动引脚 —— Renode 里 ODR 读数纹丝不动,当场抓包。
```

错在哪：配置写进了 `CRL`——低半段的户口本。`0x2 << 20` 写进 CRL，配的是 `(20-0)/4 = 5` 号脚，PC5 莫名其妙成了 2MHz 推挽输出，而 PC13 的四位原封不动，还是浮空输入。

咱们把翻车现场在 Renode 里复现一遍：时钟合闸、**CRH 不配**、直接写 BSRR（EXP-5）：

```text
--- CRH before (model reset):
0x00000000
--- write 0x00002000 to BSRR, then ODR:
0x00000000        ← ODR 纹丝不动
```

这个坑阴在哪：编译零警告，运行零报错，BSRR 的写入"成功"返回，程序欢快地跑着循环——只有灯知道真相。翻车排查时，"写 BSRR 前先读一眼 CRH/ODR"是救命的第一反应：配置没落地，后面全是空转。至于"为什么浮空输入模式下输出寄存器不驱动引脚"——引脚内部那两片 MOS 管和这四位配置的电路关系，正是下一篇的主菜，这里先记账。

## 翻身的三条路

户口上好了，PC13 已经是输出脚。现在要它高低电平翻转，手册给了三条路。

**第一条：ODR，读改写。**`GPIOC->ODR ^= 0x2000` 或 `|= / &= ~`，上一篇见过的三件套——`ldr` 读回、`orr/bic/eor` 改、`str` 写回。它有个先天破绽：**读和写之间有个窗口**。想象主循环正在配置 CRH 的读改写走到一半，中断进来，ISR 也动了同一个寄存器，中断返回后主循环把旧值加自己的修改写回去——ISR 的修改被无声覆盖。单线程裸机下这病不发作，一旦中断和主循环共享外设，它就是定时炸弹。今天只立此存照，真刀真枪的现场第五站按钮中断里见。

**第二条：BSRR/BRR，单写直达。**

```text
08000178: 6125    str   r5, [r4, #16]   ; BSRR ← 0x2000,置位 PC13
08000182: 6165    str   r5, [r4, #20]   ; BRR  ← 0x2000,复位 PC13
```

一条 `str`，完事。原子性从哪来：BSRR 的语义是**写 1 生效、写 0 无视**——低半字 bit0-15 是置位区，写哪个位哪个脚被顶高；高半字 bit16-31 是复位区，写哪个位哪个脚被拉低。硬件按位独立处理这次写入，不依赖"先读回旧值"，也就没有窗口期。BRR 是 BSRR 高半字的分身，专管复位，语义更直白。两区撞车怎么办：BSRR 一个写里同名位 set 和 reset 同时为 1 时，reset 赢（RM0008 原文规定）。

`01_register_led` 用的就是这条路：`BS13` 写 `0x2000`（1<<13）灭灯、`BR13` 写 `0x2000` 拉低点灯——记住 Blue Pill 的 LED 接在 PC13 上是低电平点亮，所以"复位"反而是"亮"。

**第三条：位带，一个位配一个专属地址。**Cortex-M3 的地基里埋了件巧宗：外设区头一兆（`0x40000000`-`0x400FFFFF`，GPIOC 的 `0x40011000` 在内）和 SRAM 头一兆的每一个位，都在别名区里有一个自己的 32 位地址。对别名地址写非零，本尊位置 1；写零，本宗位清零——硬件保证，单次访问原子。地址的算术：

```text
别名地址 = 0x42000000 + (字节偏移 × 32) + (位序号 × 4)

GPIOC_ODR 的 bit13:
0x42000000 + (0x4001100C - 0x40000000) × 32 + 13 × 4
= 0x42000000 + 0x1100C × 0x20 + 0x34
= 0x42000000 + 0x220180 + 0x34
= 0x422201B4
```

口说无凭，Renode 里实测（时钟合闸后）：

```text
--- bit-band write 0x1 to 0x422201B4, then ODR:
0x00002000        ← bit13 应声而起
--- bit-band write 0x0 to 0x422201B4, then ODR:
0x00000000        ← 应声而落
```

一个地址、一条指令、一个位——比 BSRR 还省一个"算掩码"的步骤，读单个位也一样原子。代价是那个魔数地址可读性稀烂，所以库代码里少见裸写，通常拿宏包一层。三条路摆一起：

| 路 | 指令数 | 原子性 | 读回来 | 适用 |
|----|--------|--------|--------|------|
| ODR 读改写 | 3 | 无窗口保障 | 顺路能读 | 单线程、不在乎干扰 |
| BSRR/BRR | 1 | 单写原子 | 不行 | 中断在场时的正选 |
| 位带别名 | 1 | 读写都原子 | 单位可读 | 高频单位操作、ISR 标志 |

到这里，裸寄存器点灯的账全部结清：开钟（第二篇）、上户口（本篇上半）、翻身（本篇下半）。但咱们还欠着一笔良心债：`CNF=00` 凭什么叫"推挽"？浮空输入到底"浮"在哪？四位配置拧过去，引脚里面的电路发生了什么？下一篇下到电路层，把这笔债还了。

## 您来动手

1. 算一遍 PC2 的户口：它住在 CRL 还是 CRH？四位是哪几位？2MHz 推挽输出时这两条配置代码怎么写？
2. Renode 里合闸时钟后，手工把 CRH 配成 `0x00300000`（MODE=11，50MHz），再跑固件——观察翻转行为有没有可见差别，想想为什么；
3. 用位带公式手算 IDR（`0x40011008`）bit0 的别名地址，Renode 里读它，和直接读 IDR 对账；
4. 把 `register_led` 的 `main` 里 BSRR 那行改成 `GPIOC->ODR ^= 0x2000`，反汇编对比前后 `main` 的指令数差几条。

## 欸欸！自查一下再走

- PC13 的四位为什么在 CRH 的 bit23-20？拿 `(13-8)×4` 现场推一遍；
- 复位默认 `0x44444444`，每个脚的默认户口是什么？这种默认为什么对上电安全很重要？
