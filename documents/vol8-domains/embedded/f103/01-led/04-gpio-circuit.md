# 补充篇：引脚是一片电路——推挽、开漏与施密特

前三篇把操作线走完了：地址、时钟、配置、翻转，一路都是软件视角。但账上还欠着一笔：`CNF=00` 凭什么叫"推挽"？浮空输入"浮"在哪？03 篇那次翻车里，为什么模式没配成输出，BSRR 写了、输出驱动器却装聋？这一篇下到电路层把债还清。它是补充篇，跳过不影响主线连贯；但嵌入式这行想在坑前止步，电路的直觉迟早要补——不如趁热。

先立一块牌子：**GPIO 不是"软件"，是一片真实的电路**。咱们写的每一行代码都只是在"下令"，执行命令的是引脚里面几十个晶体管。`GPIOC->CRH = ...` 拧的那四位，拧的是电路的挡位。

## 引脚的解剖图

一个 GPIO 引脚，扒开看是这么一副骨架（RM0008 第 9 章的框图翻译版）：

```text
                          VDD (3.3V)
                            │
                     ┌──[弱上拉 ~40kΩ]──┐
                     │  ┌─[弱下拉 ~40kΩ]─┼──┐
                     │  │                │  │   ← 软件启用/停用
        ┌────────────┴──┴────┐    ┌─────┴──┴─────┐
   保护二极管 ×2              │    │              │
   (钳位到 VDD/VSS)     施密特  │    │   输出驱动器   │
        │               触发器 │    │   P-MOS 上管   │
        │                  │   │    │   N-MOS 下管   │
        │                  ▼   │    │      │        │
        │              输入锁存/IDR │  ODR→ 驱动    │
        └──────────────●────────┴────┴──────┘
                    引脚 Pin
```

从外往里：**保护二极管**一对，把引脚电压钳位在 VDD+0.3V 和 VSS-0.3V 之间，静电和浪涌先过它们；**上下拉电阻**一对约 40kΩ 的弱电阻，软件决定接不接；**施密特触发器**是输入信号的守门员；**输出驱动器**是两只 MOS 管组成的跷跷板。输入路径和输出路径并联在同一个引脚上，`CNF`/`MODE` 四位决定哪条路上岗。

## 输出侧：上下两管的跷跷板

`CNF=00`（推挽）时，输出驱动器是这个造型：

```text
        VDD (3.3V)
          │
      [P-MOS]  ← 上管
          │
          ●────────  引脚
          │
      [N-MOS]  ← 下管
          │
         VSS (GND)
```

ODR 写 1：上管导通、下管关断，引脚被"推"到接近 3.3V——"推"（push）说的是电流从 VDD 经上管流向外部负载。ODR 写 0：上管关、下管通，电流从外部经引脚被"挽"（pull）回 VSS，引脚压到接近 0V。**任意时刻总有一只管子在主动驱动**，这就是"推挽"的构造性含义：两个方向都是低阻抗输出，电平确定、边沿陡峭（几十欧姆的导通电阻对上负载，开关干脆利落）。

驱动能力有硬指标：F103 普通引脚单脚绝对最大 25mA（数据手册电气特性），日常给 LED 供几毫安绑绑有余。但 PC13 不是普通引脚——见本篇后半，它有 3mA 的天花板。

## 开漏：只有下管的电路

`CNF=01`（开漏）把上管撤了：

```text
        VDD
          │
   [外部上拉电阻]  ← 芯片外的事!
          │
          ●────────  引脚
          │
      [N-MOS]
          │
         VSS
```

写 0：下管导通，引脚拉到地——这条路还在。写 1：下管关断，**然后就没有然后了**——上管不存在，引脚和 VDD 之间没有通路，它浮空（高阻态）。要输出"高"，得靠外接上拉电阻把引脚慢慢拽上去；拽多快，看电阻多小；漏多少电流，看电阻多大——工程没有免费午餐。

那要开漏干嘛？三个正经场景。其一，**I2C 总线**：协议要求多设备共线、人人能拉低、谁也不许主动推高——推挽上来就是短路，开漏加上拉天生守规矩（第五站 I2C 见真章）。其二，**线与**：多个开漏输出共一个上拉，任何一个拉低整条线就低——"与"逻辑不用门电路。其三，**电平转换**：上拉接到 5V，输出高就是 5V，3.3V 的芯片跟 5V 的老设备握手（前提是引脚 5V 容忍）。

用开漏点 LED 的坑顺手指认：输出"高"时引脚浮空，LED 阳极电压悬而不决——灯要么不亮要么半死。症状和 03 篇那次翻车一模一样：代码全对，灯不理你。所以点灯选推挽，开漏留给总线。

## 输入侧：施密特与上下拉

轮到输入路径。第一个问题是：引脚上的连续电压，怎么变成 IDR 里的 0 和 1？中间站着**施密特触发器**——一个带迟滞的门槛：电压爬过高阈值才算 1，跌过低阈值才算 0，两个阈值之间维持原判。为什么这么设计：真实信号有噪声，如果只有一个 2.0V 的门槛，慢信号在 2.0V 附近抖，输出就跟着抖成一串毛刺；有了迟滞带，小噪声掀不起翻案。按键抖动、长线感应，第一道防线都在这里。（具体阈值数值是数据手册电气特性表的地盘，不同引脚类型不同，用的时候去查，不背。）

第二个问题是悬着的引脚读出来是什么——**不确定**。这就是"浮空"（`CNF=01` 且不接上下拉）的本义：引脚电平由环境电磁场、手指静电、临近走线互相推搡决定，万用表量它读数乱跳。复位默认值 `0x44444444` 让所有脚浮空输入，是"最中性"的出厂态——不主动、不拒绝、不负责。

要一个确定的默认电平，上下拉电阻出场：`CNF=10` 时，ODR 对应位写 1 接通上拉（引脚默认高）、写 0 接通下拉（默认低）。对，您没看错——**F1 的输入上下拉选择藏在 ODR 里**，这是 F1 独一份的怪设计（F4 起才挪进专门的 PUPDR）。约 40kΩ 的弱电阻：弱到按键按下时直接被接地短路拉低，强到松手后能把引脚拽回默认电平。按键检测的标准姿势——引脚配上拉、按键接地、读下降沿——第五站就靠它吃饭。

## 回到 Blue Pill：低电平点亮的电路账

最后把咱们这盏灯的电路账算清。Blue Pill 的板载 LED 接法是"灌电流"式：

```text
   3.3V ──[限流电阻 R]──[LED]── PC13
```

LED 正极经限流电阻挂 3.3V，负极接 PC13。PC13 输出低（下管导通）：电流从 3.3V 经电阻、LED 流进引脚、经下管入地，灯亮——电流"灌"进引脚。PC13 输出高：两端都是 3.3V 量级，没有压差，没有电流，灯灭。**这就是"低电平点亮"的全部秘密**：不是软件逻辑反转，是 LED 的接法决定了谁亮。换"源电流"式接法（LED 从引脚流向地），高电平才亮——两种板子都常见，先看原理图再写极性。

限流电阻的账：LED 正向压降约 2V（红光典型），电阻上分到 `3.3 - 2.0 = 1.3V`。以 Blue Pill 常见的几 kΩ 阻值算，电流在零点几到一毫安级——现代 LED 这个量级就够亮。电阻要是没了呢：LED 压降被钳在 2V 左右，剩下的 1.3V 全压在引脚的 MOS 管上，电流由管子的导通电阻决定，轻松冲破 25mA——LED 命短，管子发热，皆大不欢喜。限流电阻不是装饰，是这道电路的命。

PC13 的脾气也得交代。它和 PC14/15 由**备份域**供电（为了 RTC、侵入检测、LSE 晶振这些断电后还得活的機能），这份特殊待遇附带严格配给：输出模式限速 2MHz、电流 3mA 封顶（数据手册 DS5319 电气特性里写得明明白白）。咱们配 `MODE=10`（2MHz）不是随手——是 PC13 顶格才 2MHz，配 50MHz 属于写了个寂寞。好在点一毫安级的 LED，3mA 绰绰有余。

## 模式表回收

现在回头看 03 篇那张组合表，每一行背后都是一片具体电路：

| 组合 | 电路里发生的事 |
|------|---------------|
| 模拟输入 | 施密特触发器断开（省电防干扰），信号直通 ADC |
| 浮空输入 | 只有施密特站岗，引脚电平随缘 |
| 上拉/下拉输入 | 40kΩ 弱电阻给引脚一个默认电平，等外部来翻转 |
| 推挽输出 | 上下两管交替主动驱动，双向低阻抗 |
| 开漏输出 | 只剩下管，高电平外包给外部上拉 |
| 复用 | 输出驱动器的方向盘交给片上外设（USART/SPI/TIM） |

03 篇翻车的电路层解释也到账了：配置留在浮空输入，意味着**输出驱动器根本没上岗**——两只 MOS 管都对 ODR 的号令装聋，BSRR 写得再勤，引脚纹丝不动，ODR 也没有输出路径可走（Renode 模型把这层逻辑演得忠实）。软件视角的"配置没生效"，落到电路视角就是"执行机构没通电挂挡"。

从下一篇起，咱们开始爬抽象的楼梯：C 宏怎么把今天这些地址和位包起来，包出了哪些暗伤。带着电路的底子上楼，看什么都是透明的。

## 您来动手

1. 拿 Blue Pill 原理图（网上搜 "Blue Pill schematic"）找到 PC13 那条支路，确认 LED 方向和限流电阻阻值，算出点亮电流；
2. 把 `register_led` 的 CRH 配置改成开漏（`CNF=01`：`(0x6u << 20)`），烧进 Renode 看 ODR 翻转是否照旧——再想想真机上 LED 会怎样；
3. 查数据手册 DS5319 的 GPIO 电气特性表，找到普通引脚和 PC13-15 的电流限额原文，核对本文的 25mA/3mA；
4. 想一个问题：如果把 LED 从"灌电流"改成"源电流"接法（LED 从引脚流向地），代码里哪一行要改？
