# 卷五 Project：并行图像卷积工作台

## 项目定位

把卷五的家当全部用进一个真实的小程序：`blur`——一个并行图像卷积工作台。单线程基准、多线程分块、确定性校验、TSan/UBSan 质量门、中位数性能报告，一个不缺。图像处理是「分块无依赖」的典型可并行负载，但它的瓶颈不在计算而在**内存带宽**——做完你会对「先量再优化」有肌肉记忆。

任务分四层，一层一层往上盖；卡住了看[参考实现](15-project-solutions.md)，它按层组织，可以只读你卡住的那层。

> 环境：g++ 16 / clang++ 22，C++20。质量门用 `-fsanitize=thread -g` 与 `-fsanitize=address,undefined -g`（都是**编译期**选项）。所有性能数字都按 ch08-02 的方法论：预热 1 轮 + 5 轮取中位数，并**如实报告**你的机器。

## 任务分层

### 核心任务（L2）：能跑起来的模糊器 {#pj-core}

**L1 热身**：先把类型与串行版搭起来——`struct Image { int width, height; std::vector<float> pixels; }`，一个 `make_random_image(w, h, seed)`（固定种子保证可复现），以及串行 3×3 盒式模糊（边界 clamp-to-edge，即越界坐标夹回图内）的函数骨架，先只求编译通过、跑出第一张模糊图。

实现 `blur_serial`：对每个像素取 3×3 邻域（边界夹回）求平均。再实现 `blur_parallel_chunk(src, workers)`：把输出**行区间**切成 workers 段，每段一个 `std::thread`，各线程只写自己的输出行。

**验收标准**：`blur_serial` 与 `blur_parallel_chunk(8)` 逐像素最大差值 **exactly 0**；贴出一次 4096×4096 运行的正确性输出与 `-O2` 构建命令。

[参考实现 →](15-project-solutions.md#pj-core)

### 进阶任务（L3）：确定性校验与缩放曲线 {#pj-adv}

三件事。①把校验自动化：`max_diff(a, b)` 返回逐像素最大绝对差，并行版与串行版必须为 0。②测缩放曲线：串行与 chunk(1/2/4/8) 各测一次（按方法论预热 + 中位数），贴出耗时与加速比——**如实说明**为什么 8 线程加速比远小于 8（想想负载是什么受限：计算、带宽、还是锁？）。③回答：为什么「每线程写**互不重叠的输出行**」让这个并行版**根本不需要任何锁或原子**？

**验收标准**：贴出 max_diff 输出与缩放表；一句话说清不需要同步的依据（引用 ch01 的分区并行原则）。

[参考实现 →](15-project-solutions.md#pj-adv)

### 再进阶任务（L4）：把门装上 {#pj-gates}

三件事。①质量门：512×512 小图 + 4 线程版本分别用 TSan 与 ASan+UBSan 构建跑通，零报告贴输出。②确定性：换一个随机种子（比如 7）再跑一遍小图校验，说明「固定种子」在并发正确性回归里的作用。③性能报告方法论：贴出你用的预热/轮数/取中位数的实现（或说明），并指出为什么并发基准**不该**用单次运行的数字。

**验收标准**：贴出两个 sanitizer 构建的输出、换种子后的校验输出、以及一段方法论说明。

[参考实现 →](15-project-solutions.md#pj-gates)

### 终极挑战（L5）：性能攻坚 {#pj-l5}

三件挑战（L5＝用本卷知识可解的最难问题，档位口径见[卷五练习体系](index.md)；风格改编自 Stanford CS149 并行计算课程图像作业与「内存带宽受限优化」类工程题）。①实现 `blur_parallel_striped`（行交错分派：worker w 处理 `y % workers == w` 的行），与 chunk 版对比——两者**数值结果必须完全一致**，性能谁好？为什么（想清楚输出行的缓存行归属与写分配）？②实现分离卷积：3×3 盒式模糊 = 先水平 3 点均值、再垂直 3 点均值，两遍各并行。数学上等价（边界 clamp 下也等价，动手验证：最大差应为 0 或仅浮点舍入量级 1e-7），算力从 9 次加法降到 6 次——**但本机它很可能反而更慢**，把「为什么」量出来并解释（提示：两遍 = 两倍内存流量，本负载是带宽受限还是计算受限？）。③交一份 200 字以内的性能报告：你的机器、三种并行策略的中位数耗时、以及「算法复杂度优化」失效时该信谁。

**验收标准**：贴出三种策略的 max_diff 与中位数耗时；报告里必须用「内存流量」解释 separable 的失利，而不是一句「带宽瓶颈」了事。

[参考实现 →](15-project-solutions.md#pj-l5)
