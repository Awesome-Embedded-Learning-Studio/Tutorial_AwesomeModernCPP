# TypeScript 代码规范

目标是让接手的人能直接读懂代码及其正确性依据。简洁以省去重复为准，不以压缩行数为准；新代码与修改到的逻辑按本规范整理，避免无关的全仓格式改动。

## 命名与结构

- 使用 2 空格缩进、单引号、分号；每行只做一件事。分支里的多步操作展开成多行，禁止把赋值、调用、return 挤在同一行。
- 变量和函数用 camelCase，类型和类用 PascalCase，模块常量用 UPPER_SNAKE_CASE。名称说明含义和单位，如 operandBits、byteLength、stackOffset；循环索引 i、架构名称 rip/rsp/ModRM 等在局部上下文中可保留。
- 函数只负责一个可命名的步骤。解码、寻址、标志计算与执行各自隔离；长分支中的独立算法提取为具名方法，不为一行表达式增加空壳抽象。
- 优先提前返回，减少嵌套。复杂条件先命名，禁止嵌套三元表达式；同类 opcode 的 switch 分支可以并列标签，分支体展开书写。

## 类型与边界

- 保持 strict，通过具名接口、字面量联合和可辨识联合表达消息与状态；Worker 请求和响应使用共享协议类型。
- 外部输入先使用 unknown 并校验，避免 any。类型断言和非空断言只用于已有明确保证的内部不变量，并在定义处说明保证来源。
- 导出函数、公共方法及复杂辅助函数声明返回类型；局部简单表达式保留类型推导。类型导入使用 import type 或行内 type。
- 地址、寄存器值、立即数与标志位计算全程使用 bigint。只将尺寸、计数、已验证处于映射内的字节偏移转换为 number；编码寄存器值使用 DataView 的 BigInt 接口，不先转换为浮点数。
- 位宽（bit）和内存尺寸（byte）分开命名，在内存接口处显式转换。不得使用宽泛的字符串替代有限的指令或消息类型。

## 注释、异常与验证

- 注释解释原因、契约和架构陷阱，避免逐句翻译代码。未定义标志位必须标明实测语料来源与适用范围，不把某台 CPU 的行为写成 ISA 保证。
- 错误包含可定位的指令、PC 或内存地址；不可支持的语义明确报错。禁止吞掉执行异常后伪造成功状态。
- 不手改黄金轨迹来适配实现。新增执行语义优先补充汇编场景，由 as/ld 生成机器码、原生 GDB 采集参考，并逐步比较寄存器与完整栈。
- 修改后完成 README 中的类型检查、单元/GDB 对拍、工具测试、构建、分发检查和浏览器验证；仅格式整理不编写镜像实现的测试。
