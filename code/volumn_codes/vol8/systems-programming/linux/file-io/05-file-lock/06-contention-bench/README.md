# 06-contention-bench —— 锁竞争计时(E6)

环境:台机 Ryzen 7 9700X(16 线程),WSL2 内核 6.18.33.2,数据文件在 ext4。口径:8 个 fork 出的子进程各自独立 open,管道对齐起跑线,3 轮取中位数。

## 原始数据(`contention.out`,单位 ms)

| 模式 | r1 | r2 | r3 | 中位数 |
|---|---|---|---|---|
| locked(8×100 轮,临界区 usleep 10ms) | 8090.4 | 8090.5 | 8091.1 | **8090.5** |
| free(同样 8×100×10ms,不拿锁) | 1009.8 | 1009.9 | 1009.9 | **1009.9** |
| micro(8×2000 轮空临界区 lock/unlock) | 252.3 | 255.7 | 270.0 | **255.7** |

## 解读

- **locked ≈ 8090 ms vs 理论串行 8000 ms**:互斥把 8 份并行的 10 ms 睡眠串成一条队,多出的 ~90 ms 就是 800 次锁交接 + 调度的开销。三轮极稳(±0.7 ms),这是串行化路径,不吃调度抖动。
- **free ≈ 1010 ms**:对照——8 份 10ms×100 轮完全并行就是一轮的时长。8 倍差距是**互斥本身的代价**,不是 flock 慢。
- **micro ≈ 255.7 ms / 16000 次交接 ≈ 16 µs/次**:8 路争抢下「拿到锁→交给下一个」的纯开销。旁证测量(同机同轮,同一 fd 上无争抢连打 1000000 对 lock/unlock):**0.675 µs/对**——争抢把每对的开销放大了 ~24 倍(睡眠-唤醒路径)。
- 写放大视角:如果临界区只有 10 ms,锁开销占比 ~1.1%(90/8090)——**临界区够长时锁不贵;临界区趋近于零时,16 µs/次的交接费才是地板**。

## 复现

```sh
mkdir -p ~/l05_scratch/e6
g++ -std=c++20 -Wall -Wextra -Wpedantic -O2 -I ../common contention.cpp -o /tmp/e6
/tmp/e6 | tee contention.out    # 约 28 s(3×8s + 3×1s + micro)
```
