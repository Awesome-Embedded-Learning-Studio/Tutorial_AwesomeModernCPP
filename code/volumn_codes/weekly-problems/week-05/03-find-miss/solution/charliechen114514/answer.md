**思路**:

空里填的是 `end()`。咱们先把 std::find 的规矩念清楚:找到目标,返回指向它的迭代器;没找到,它把您传进去的第二个实参(那个「最后一个元素的再往后」)原样还给您。所以判「真没找到」,您手里能拿到的信号只有一个:返回值和 `v.end()` 相等。标准写法就是这一行:

```cpp
if (it == v.end()) {
    return 1;   // 真的没找到
}
```

为什么偏偏和 end() 比?因为迭代器不是指针。GCC 自带的标准库实现叫 libstdc++,咱们这题里,它把 `vector<int>::iterator` 做成一个类类型,下面报错里的 `__gnu_cxx::` 前缀就是它内部的命名空间。拿 `it` 和 `nullptr` 比,GCC 当场拒绝,笔者实测的报错:

```text
error: no match for 'operator==' (operand types are
'__gnu_cxx::__normal_iterator<int*, std::vector<int> >' and 'std::nullptr_t')
```

咱们再拿它和 `v.back()` 比,也一样编不过:back() 交出来的是元素本身,一个 int,一边迭代器一边 int,对不上号。就算哪天碰上拿裸指针当迭代器的实现,指针比法碰巧能编,那也是撞运气——标准给的判法只有一个,和 end() 比。

这条规矩是整个算法库的通用约定:find、find_if 找不到,还您 end();count 查不到,还您 0;remove 挪完元素,还您「新逻辑末尾」。都是同一句话:拿不到有效结果,就还您一个末尾位置。周日那道压轴题,咱们就要拿 remove 还回来的末尾去裁容器。

**排错**:

最常见的错填是 `back()`:您想成「没找到就指最后一个」,类型对不上,编不过。其次是 `begin()`:它也是合法迭代器,能编能跑,可语义全反。「等于 begin()」说的是「目标恰好是第一个元素」;99 不在开头,这条 if 永远不成立,程序永远走 return 0,把「没找到」报成了「找到」。还有填 `end` 漏了括号的:end 是成员函数,得调用才拿得到迭代器,判题要的正是带括号的 `end()`。
