**思路**:

整题三步:读、存、打。读的部分一行 `while (std::cin >> x)`:流读到输入结束,提取失败,循环自己就停了。存的位置笔者选 `std::set<int>`,一趟 insert 把两件事同时办妥:重复的数,第二次 insert 进不去,这叫插入即去重;set 内部始终按 `std::less` 排着序,遍历拿到的就是从小到大,这叫遍历即升序。咱们对着 solution.cpp 看:

```cpp
    std::set<int> s;
    int x;
    while (std::cin >> x) {
        s.insert(x);
    }
```

打的部分藏着一个格式细节:第一个数前面不能有空格。判题是整行逐字符比对,您在这儿多打一个空格,四组全红。参考实现的办法是那个布尔标记 `first`:第一个数打完就放倒它,之后的数才在前面补一个空格:

```cpp
    bool first = true;
    for (int v : s) {
        if (!first) std::cout << ' ';
        std::cout << v;
        first = false;
    }
    std::cout << '\n';
```

末尾的 `'\n'` 您也别省,判题数据每一组的期望输出都带着换行。不走 set 也办得成:咱们读进 vector,`std::sort` 排好,`std::unique` 把相邻的重复压成一个,再拿 erase 裁尾巴。unique 和 remove 是一家子,都只搬不删,都返回一个「新逻辑末尾」:从那里到 v.end() 是要扔的尾巴,erase 裁的就是这一段。周日那道压轴题,咱们还要跟这套写法正面碰一次。

**排错**:

还是不通过?您先盯行首:打印写成每个数前面带空格(比如 `std::cout << ' ' << v`),输出就成了「 1 3 5」,肉眼几乎看不出差别,判题说不一样就是不一样。再看行尾:漏了 `'\n'`,或者最后一个数后面多打一个空格再换行,同理过不了。最后看读入:要是图省事写了 `while (std::cin.good())`,输入结束那次失败的提取之后还会多 insert 一次——判题数据全是整数时它碰巧无害(x 保留旧值,而旧值早就在 set 里了),可提取一旦撞上非数字,失败那次会把 x 写成 0,输出里凭空多一个 0,这一条笔者实测过。老老实实 `while (std::cin >> x)`,这些毛病一个都不沾。
