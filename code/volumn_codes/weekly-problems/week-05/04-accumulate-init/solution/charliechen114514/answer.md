**思路**:

程序输出,笔者实测是:

```text
3 4.0
```

门道全在 accumulate 的第三个实参上。咱们看它的原型:

```cpp
template <typename InputIt, typename T>
T accumulate(InputIt first, InputIt last, T init);
```

您盯着模板参数 T 的来源看:它只从 init 推导,容器里装什么类型,它一眼不看。init 写 0,T 就是 int,累加变量是个 int;init 写 0.0,T 就是 double,累加变量一路 double。两条路咱们各走一遍:

- 写 0:累加变量是 int。第一步 0 + 1.5,加法在 double 里做,得 1.5;可这个和得存回 int 的累加变量,向零截断,存成 1。第二步 1 + 2.5 得 3.5,存回 int,截成 3。a 本身声明成 int,%d 打出来是 3。
- 写 0.0:累加变量从头到尾是 double,0.0 起步,加 1.5 得 1.5,加 2.5 得 4.0,b 打出来是 4.0。

您留神「向零截断」四个字:3.5 截成 3,不是四舍五入到 4;哪天您加出 3.9,照样得 3。

往后给 double 容器求和,初始值都老老实实写 0.0。这题的原始程序,笔者开 -Wall -Wextra 实测过,零警告,错得悄无声息,所以才值得先亲眼见它一次。顺带提醒一句,`std::accumulate<double>(...)` 这种显式模板实参救不了场:模板参数表里排在头一个的是迭代器,您这个 double 填到它头上去了,编不过,笔者也实测过。写 0.0,一步到位。

**排错**:

高频错答「4 4.0」:您把截断记成了四舍五入,3.5 被进位成 4。第二高频「3.5 4.0」:知道加法在 double 里做,忘了每一步的和都要存回 int 的累加变量——截断每加一步就发生一次,等不到打印那一刻。还有猜「3 3.5」的:a 声明成 int、printf 用 %d,小数部分从头到尾没有出场机会。
