**思路**:

打印的是 A。您要是答了 B,这份参考答案正是为您写的;答了 A 但说不出所以然,咱们把机制拆开看。

`if (ok)` 走的这步,是 optional 自己的 bool 转换。这个转换只回答一个问题:值存进去了吗。存了(不管存的是 true 还是 false),转换结果就是真;没存,也就是 nullopt,转换结果才是假。`ok` 里存着 false,「存着」这件事成立,所以进的是 A 支。咱们把三种情况摆在一起,笔者都实测过:`ok = false` 打印 A;`ok = std::nullopt` 打印 B;`ok = false` 但判 `ok.value()` 时打印 B。

要按里面的值判,咱们把两条写法摆出来:

```cpp
if (ok.value()) { /* ... */ }   // 没存值时抛 std::bad_optional_access
if (*ok) { /* ... */ }          // 没存值时是未定义行为
```

`.value()` 和 `*ok` 都要求 optional 里确实存着值,区别在没存时的待遇:前者抛 `std::bad_optional_access`,后者直接未定义行为。这题的程序里 ok 一定存着值,两条都安全;真实代码里 optional 常常是「可能有」,这时候咱们得先确认存了、再看值:

```cpp
if (ok && *ok) { /* ... */ }
```

`ok && *ok` 前一半先问存没存,后一半才看值,顺序不能反——`*ok` 单独落在没存值的 optional 上就是未定义行为,而 && 左边为假时右边根本不求值,这个短路顺序正好就是您要的顺序。

optional<bool> 名声不好,根子就在这题:一个类型同时背着「存没存」和「真假」两层语义,if 一眼扫过去,您分不清判的是哪层。真要表达「真、假、没结果」三态,一个带三个枚举值的小类型往往更诚实。压轴题能让您把「存着 false 也能走进 if」这件事记住,任务就算完成了。

**排错**:

答错最常见的形式,是把「存了 false」当成「条件不成立」,顺口答 B。咱们拿 nullopt 把界线画清:让 if 走 else 的唯一方式是没存值;只要存着值(哪怕值是 false),if 都当条件成立。这条直觉带进真实代码,代价不小:比如拿 optional<bool> 当「配置项查到没有」的返回值,`if (found)` 一写,查到且为 false 的配置就和查到且为 true 的进了同一个分支,「没查到」倒是被分开了,和您想表达的正好岔开一层;而且它不报错,默默走错路。
