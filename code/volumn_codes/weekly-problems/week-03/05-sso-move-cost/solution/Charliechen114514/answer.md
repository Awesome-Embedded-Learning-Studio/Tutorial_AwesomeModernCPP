**思路**:

一问:s 处在「有效但未指定」的状态——能析构、能赋新值、能调无前置条件的成员;「一定变空」不是标准承诺(三大实现确实都置空,本地实测 libstdc++,`s.size()` 得 0)。这题与本周第 3 题是同一件事,不再展开。

二问:不是。教科书说的「偷指针」只对**堆上的长字符串**成立。而 "hello world" 一共 11 个字符,正好在 SSO(Small String Optimization,短串优化)生效的范围内:字符串不长时,数据直接存在 `string` 对象**自己内部**的一小块缓冲区里,根本没有堆指针可偷。移动构造面对这样的串,只能把内部缓冲一个字符一个字符抄过去,再把源串置为有效状态——线性时间。比起拷贝,省下的只有堆分配那一步,字符搬运一次没少。本地实测(libstdc++,64 位):`sizeof(std::string)` 为 32,短串 `capacity()` 为 15,数据地址就落在对象自身这 32 字节里;移动之后,新串的数据待在**新对象**内部,源串 `size()` 归 0。

三问:换成 500 个字符,答案就变了。长串的数据在堆上,`string` 对象里只存指针和长度——移动构造偷走指针、把源置空,常数时间完事。本地实测同一段代码:500 字符的串,移动后新串数据地址在对象外部(堆上),源串 `size()` 归 0。同一行代码,两种行为,分界线就是 SSO 的内联容量:libstdc++ 和 MSVC 是 15 字符,libc++ 是 22。11 个字符,在哪个实现里都是短串。

把这题放在压轴,是想纠正一个普遍印象:写了 `std::move` 就是免费的。`std::move` 本身只是一次到右值的转换——《Effective Modern C++》条款 23 的原话,它不移动任何东西;真正干活的是后面的移动构造,而它快不快、省不省,取决于类型怎么实现。`string` 的短串移动照样是线性时间;同理,`const` 对象接住 `std::move` 会静默落回拷贝,没有移动构造的类型也一样。`std::move` 提供的只是「允许移动」,不保证移动一定划算。

教程 vol3 讲 `string` 深入的那篇(SSO、COW 与 resize_and_overwrite)把这套内存模型拆得更细,推荐连着读。

**排错**:

- 想用 `capacity()` 判断短串长串:实现各异,libc++ 的 22 和 libstdc++ 的 15 会给出不同答案——不过 11 字符在谁家都是短串,题面这个例子不受影响。
- 去 Godbolt 验证时别开 `-O2`:优化一上来,逐字符的复制循环和指针搬动全被压糊了,开 `-O0` 才看得清结构。
