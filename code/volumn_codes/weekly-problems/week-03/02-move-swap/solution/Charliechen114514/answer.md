**思路**:

对着 solution.cpp 看:

```cpp
template <typename T>
void my_swap(T& a, T& b) {
    T tmp = std::move(a);
    a = std::move(b);
    b = std::move(tmp);
}
```

三行,每行一次移动:`std::move(a)` 把 a 移动到临时对象 tmp;`a = std::move(b)` 把 b 移动到 a;最后 tmp 里存着的是 a 原来的值,再移动到 b。全程走 `Box` 的移动构造和移动赋值,`SwapStats::copies` 一次都不加——判题器核对的就是这个数。

为什么非要这么写?把三行里的 `std::move` 全去掉,写成 `T tmp = a; a = b; b = tmp;`,值照样换对,但三行全落到拷贝构造和拷贝赋值上。对 `Box` 这种小类型无所谓;换成 `std::vector`,就是三份深拷贝。C++11 之后标准库的 `std::swap` 就是上面这三行移动(移动构造对大多数类型只是搬指针和几个整数),交换两个大容器的开销从三份深拷贝降到三次移动——交换变便宜,靠的就是移动语义。

顺带一句工程上的正解:平时交换值,直接 `using std::swap; swap(a, b);` 让 ADL 找到类型的定制版本,C++20 起还有 `std::ranges::swap` 一站到底。这题要您手写一遍,是为了亲眼看见这份便宜是从哪省出来的。

**排错**:

- 拷贝数不是 0:某一行忘了 `std::move`,最常见的是 `T tmp = a;`——三行全拷的话,copies 会顶到 3。判题器把 got 和 want 都摆出来了,对着数查哪一步多了。
- 值没换对:空实现,或者三行的顺序错了。顺序是固定的:a 的值进 tmp,b 的值进 a,tmp(存着 a 原来的值)进 b,三行照这个顺序排。
- 直接在函数体里写 `std::swap(a, b);`:能过判题(它内部就是移动实现,copies 同样是 0),但这题就白做了——三行亲手写一遍,才是全部内容。
