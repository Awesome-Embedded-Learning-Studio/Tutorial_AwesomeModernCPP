**思路**:

答案是 `x = 20`。

`(a++, b++)` 是一个逗号表达式,求值规则是:从左到右,一个求完再求下一个,整个表达式的值取**最后一个**子表达式的值。咱们一步步拆:

先求左边的 `a++`:a 原来是 10,`a++` 的值是旧值 10,a 变成 11——但逗号左边这部分的值直接被丢弃,10 没人要。再求右边的 `b++`:b 原来是 20,`b++` 的值是旧值 20,b 变成 21。整个逗号表达式的值就是右边这个 `b++` 的值,即 20,赋给 x。

真跑一遍(`g++ -std=c++23`,加 `-fsanitize=undefined` 兜底):

```text
x=20 a=11 b=21
```

**变式:`x = (a++, a++);` 是 UB 吗?**

——不是!哈哈,没想到吧(其实笔者一开始也没想到 XD)。

关键在逗号运算符自己带了排序保证:C 标准里写明「逗号运算符的左操作数作为 void 表达式求值,它的求值和右操作数的求值之间有一个序列点」(C11 §6.5.17p2,附录 C 也把逗号运算符列进了序列点清单)。C++ 那边同理,[expr.comma] 写的是左边表达式的一切值计算和副作用,都 sequenced before 右边的一切。也就是说,第一个 `a++` 完整落定之后,第二个 `a++` 才开始——两次修改之间隔着序列点,不构成未定义行为。

那结果是多少?a 从 10 出发,第一个 `a++` 值是 10(丢弃),a 变 11;第二个 `a++` 值是 11,整个逗号表达式的值就是 11,所以 `x = 11`,最后 a 是 12。上面那份真跑输出同样验证了:`y=11 a=12`。

**排错**:

最常见的错答是 21——把「x 等于 b 的值」记成了「b 自增之后的值」。后缀自增交给表达式的是旧值,新值是留给 b 自己的,x 拿到的是 20。

另一类错答是 10,把逗号表达式当成了「取第一个子表达式的值」,方向正好反了——逗号要最后一个。

至于「这是 UB 吧」的直觉,来得也不冤:它确实长得像。真正的 UB 在函数实参里,`f(a++, a++)` 这种写法,两个实参的求值在 C++17 之前没有顺序保证,两次修改 a 之间没有序列点,那才是未定义行为。逗号表达式自带序列点、函数实参不带——两码事,别弄混。
