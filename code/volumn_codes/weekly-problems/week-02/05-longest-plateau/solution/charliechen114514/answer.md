**思路**:

「找最长平台」要是在未排序的数组上做,咱们得先排序或者开哈希表统计;但这题的数组**已经从小到大排好**——相等的值必然挤在一起,每个平台就是数组里的一段。于是整个问题变成一遍扫描的事:逐个读数,数当前这段连续相等的元素最长连了几个。

对着 `solution.cpp` 看:

```cpp
int best = 0;   // 见过的最长平台
int cur = 0;    // 当前平台已经连了几个
int prev = 0;   // 前一个读进来的值
```

三个变量各管一件事:`cur` 数当前平台有多长,`best` 记历史最长,`prev` 存上一个值用来比对。核心三行:

```cpp
        if (i == 0 || x != prev) cur = 1;   // 开头,或者值变了:新平台从 1 起数
        else cur++;                          // 值没变:当前平台加长
        prev = x;
        if (cur > best) best = cur;
```

读进一个数,要么和前一个相等——当前平台加一;要么不等——新的平台从 1 重新起数。`i == 0` 那个条件分支专门伺候第一个元素:它前面没有 `prev` 可比,但它自己必然是一个平台的头。`best` 顺手更新,扫完整个数组答案就在手里。四组判题数据核过:书上的例子输出 `3`,全 `7` 的数组输出 `5`,单个元素输出 `1`,全体不重复输出 `1`。

一遍扫描,n 个元素每个看一次,时间 O(n),额外空间就那三个变量。

**排错**:

最阴的坑是题面里就点了名的:**把平台的「值」当成「长度」输出**。书上的例子 `3-3-3`,值是 3、长度也是 3,两答案长得一样,您写错了照样「对」——直到判题数据里出现 `7 7 7 7 7`:长度该是 5,输出 7 就是把值当成了长度。出题时特意放了这组,就是抓它。

第二个坑藏在 `prev = x` 这行不起眼的更新上:删掉它,`prev` 永远停在 0,每个数都和 0 比对,`cur` 一辈子是 1——`7 7 7 7 7` 该输出 5,实际输出 1;书上的例子该输出 3,实际也是 1。笔者把这两个删改版本都真跑过:顺带说个有意思的发现,把 `i == 0 ||` 那个守卫删掉,这份代码在 `cur`、`prev` 都从 0 出发的初值下**碰巧**还是对的(第一个数无论走哪个分支,`cur` 都落回 1)——但那是初值替咱们兜的底,换个写法(比如 `cur` 从 1 起数)就露馅了。守卫留着,把「第一个元素必然是新平台的头」写在明面上,不靠巧合。

还有一类是 `best` 忘了在循环里更新,只在最后输出 `cur`——那输出的是**最后一个**平台的长度,前面的全白扫。判题第一组数据最长平台 `3-3-3` 在中段,专治这种。

顺带一提,要是哪天前提没了——数组没排序——这题就不能这么做了:相等的值不再相邻,得先排序(排序后同样的扫描就够)或者开哈希表按值计数。「利用前提」和「前提没了怎么办」两头都想清楚,这题才算真吃下去。
