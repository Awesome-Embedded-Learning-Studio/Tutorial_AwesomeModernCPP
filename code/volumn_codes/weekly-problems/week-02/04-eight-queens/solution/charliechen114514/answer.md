**思路**:

暴力思路是 8 个皇后枚举 8⁸ 种摆法,能跑但蠢。咱们直接用上题目里藏着的结构:**一行只放一个皇后**(两皇后同行立刻互吃,不用考虑),那么一组解就是「给 0 到 7 行各分配一列」的方案。按行往下搜,每行试一列,和上面几行放过的皇后不冲突就继续,冲突就换列——这就是回溯:一路走到底要么凑成一组解,要么半路死掉退回来换条路。

对着 `solution.cpp` 看:

```cpp
int col[10];  // col[r] = 第 r 行的皇后放在第几列(到 n = 9 都够用)
int total;
```

棋盘不用真的开二维数组,`col[r]` 记「第 r 行的皇后在第几列」,整组解就是这一个一维数组。冲突检查靠它:

```cpp
bool ok(int row) {
    for (int r = 0; r < row; r++) {
        if (col[r] == col[row]) return false;                    // 同列
        if (col[r] - col[row] == r - row) return false;          // 主对角线
        if (col[r] - col[row] == row - r) return false;          // 副对角线
    }
    return true;
}
```

同行不可能(咱们按行放),要查的只剩同列和同斜线:同列是列号相等;同斜线是「列差等于行差」——沿对角线走一步,行和列各变一格,所以两个格子若在一条对角线上,行距和列距必然相等。绝对值拆成两个不等式,写起来更快。

```cpp
void dfs(int row, int n) {
    if (row == n) {   // n 行都放满了,凑出一组解
        total++;
        return;
    }
    for (int c = 0; c < n; c++) {
        col[row] = c;
        if (ok(row)) dfs(row + 1, n);
    }
}
```

搜索本体:`row == n` 说明 n 行全放下了,`total` 加一;否则枚举这一行的每一列,能放才往下递归。放不下的分支自然死掉,循环自动替咱们「回溯」——这一格填 c 不行,试 c+1;整行都不行,退回上一行换位置。

真跑(`g++ -std=c++23 -O2`,数一遍 n 从 1 到 9):

```text
n=1 -> 1
n=2 -> 0
n=3 -> 0
n=4 -> 2
n=5 -> 10
n=6 -> 4
n=7 -> 40
n=8 -> 92
n=9 -> 352
```

`n = 8` 是 92,和流传的答案一致;顺带一提 `n = 2`、`n = 3` 是 0——2×2、3×3 的棋盘怎么摆都有一对皇后互吃,连一组解都凑不出来。

**排错**:

对角线判断是最常见的翻车点:写成 `col[r] - col[row] == r - row` 一支就完事,漏掉另一条方向的对角线,会把斜着吃的摆法也数进去,`count_solutions(4)` 就从 2 涨成别的数——这个测试值小,专门用来抓这种错。

另一个坑在「清零」:`total` 是全局的,`count_solutions` 进来先置 0 再搜。忘了这句,判题器连续调用五次,答案越加越大,第二组测试就挂了。咱们平时单测一次调用看不出问题,连着调才炸,这种错最阴。

还有一类是把 `row == n` 的边界写成 `row == n - 1`——最后一行还没试放就计数了,数出来的是「前 n-1 行互不冲突」的方案数,和答案差着量级。
