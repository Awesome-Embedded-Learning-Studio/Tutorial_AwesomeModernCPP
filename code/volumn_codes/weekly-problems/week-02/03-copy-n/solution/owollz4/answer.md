**思路**:

这题的坑全在「正好 n 个字符」上。普通复制咱们都会写——遇到 `'\0'` 就停;但这里 `src` 短了不能提前停,`dst` 后面的格子得拿 `'\0'` 填满;`src` 长了也不能多看一眼,写满 n 格立刻收工。边界想清楚,循环本身就两句话。

对着 `solution.cpp` 看:

```cpp
for (int i = 0; i < n; i++) {
    dst[i] = src[i];
```

外层循环只管「照抄」:i 从 0 走到 n-1,`src` 还有真字符就一直抄。妙处在抄完一格立刻检查:

```cpp
    if (src[i] == '\0') {
        for (i++; i < n; i++) {
            dst[i] = '\0';
        }
    }
}
```

抄到 `'\0'`,说明 `src` 到头了,这个 `'\0'` 本身也是要抄的(它正好占一格);剩下的格子从 i+1 起全部填 `'\0'`,填到 n 为止。内层循环复用了外层的 i,填完条件自然不满足,外层循环跟着结束——一个下标干完两段活。

用判题数据核一遍:`src = "ab"`、`n = 4`,`d` 四格全部预填 `'#'`,调用后前两格是 `'a' 'b'`,后两格被补成 `'\0'`,三组测试全过。

**排错**:

最常见的错法是「提前收工」:`for` 里遇到 `'\0'` 直接 `break`,结果 `src` 短的时候 `dst` 尾巴上还挂着没清掉的旧数据。判题的第一组测试专门在 `d` 里预填了 `'#'`,就是抓这个——您要是 break 了,后两格还是 `'#'`,当场失败。

反方向的错法是多写一格:抄完顺手 `dst[n] = '\0'`。题目明说了 `src` 长的时候 `dst` 不保证 NUL 结尾,只许动 `dst[0]` 到 `dst[n-1]`——多写的那格可能压根不存在,`n` 恰好等于数组长度时就是越界写。

顺带一提:这题的语义和标准库的 `strncpy(dst, src, n)` 一模一样——`src` 短则补零,`src` 长则截断,标准早就写好了。不过这题的练点就是自己把这个循环写对,写完再对照 `strncpy` 的说明书,印象比直接调库深得多。
