**思路**:

参考答案是投稿人 owollz4 的原稿 words_upper,判题程序在外面套了个 main 壳,思路由笔者代述。

咱们把整题念一遍,其实就一个循环:读到 EOF 为止,每个字符看一眼,小写就抬成大写,其余原样送回去。原稿头两行把最容易错的地方先做对了:

```cpp
    int ch = 0;
    int dif = 'A' - 'a';
```

`ch` 必须是 int,这一步咱们看仔细:getchar 的返回值要么是一个 unsigned char 范围的字节值,要么是负的 EOF,两种状态靠 int 的正负分家,题面那句「正确处理 EOF」,落点就在这。`dif` 是小写挪到大写要加的那个数,ASCII 表里大小写字母排得整整齐齐,`'a'` 加上它正好落在 `'A'`。

```cpp
    while((ch = getchar()) != EOF)
        {
            if(ch >= 'a' && ch <= 'z' )
                putchar((ch + dif));
            else
                putchar(ch);
        }
```

咱们看判断条件,它只圈住 a 到 z:数字、标点、换行、已经是大写的字母,全部走 else 原样输出。判题数据里专门放了 `MiXeD 123 !?` 和 `OK 42`,前者只有 i 和 e 两个小写被抬,后者一个字符都不许动,圈错范围当场露馅。末尾孤零零的 `return ;` 是 void 函数的收尾,原稿如此。

**排错**:

您要是把 ch 声明成 char,就顶在头号翻车点上。有符号 char 的平台上,字节 0xFF 存进去是 -1,和 EOF 分不清。无符号 char 的平台上,EOF 的 -1 存进去变成 255,循环再也停不下来。两种平台各有一种死法,而 int 一刀两断:字节值全是非负,EOF 是负的,谁也不混谁。
