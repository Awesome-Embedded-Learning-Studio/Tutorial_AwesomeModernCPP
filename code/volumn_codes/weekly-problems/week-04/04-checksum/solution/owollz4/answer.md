**思路**:

参考答案出自投稿人 owollz4 的原稿,思路由笔者代述。原稿的循环里只做了累加,漏了题面要求的「逐字符复制输入到输出」,判题版里那行 `putchar(ch)` 是笔者落题时补的,代码注释里也标了。

```cpp
    int ch = 0;
    signed char sum = -1;
    while((ch = getchar()) != EOF)
    {
        putchar(ch);   // 落题时补的一行
        sum += ch;
    }
    printf("\n%d\n",sum);
```

结构和小写变大写那题一样,循环里两件事,先回显再累加。最要紧的一行是 `sum += ch`,咱们拿判题第一组数据把它从头算到尾。输入 `Hello world!` 带换行一共 13 个字符,字符码加起来是 1127,sum 从 -1 起,加完是 1126。

sum 是 signed char,装不下 1126。加法本身在 int 里做,sum 和 ch 都先提升成 int,加完才存回 signed char。超界怎么办?咱们回头看题面那句「溢出忽略」,实义是折回:超出 -128 到 127 的部分按 256 取模绕回来。1126 减去四个 256 是 102,所以输出 102。要是按「超界部分扔掉」去理解,这个 102 就对不上了,只有折回能解释它。

printf 那行还有个小机关:实参 sum 是 signed char,传参前被提升回 int,%d 拿到的类型刚好匹配,打印正常。这些数字笔者都实测过:GCC 的 c++17/20/23 与 Clang 输出完全一致,窄化折回自 C++20 起写进了标准,GCC 和 Clang 此前也一直这么实现。

**排错**:

输出差一点,先查空行:`printf("\n%d\n",sum)` 的第一个 `\n` 就是题面要求的「先输出一个空行再打印检验和」,少写一个换行,三组判题全部错位。空输入那组专查初值:您要是顺手把 sum 写成 0 起步,三组数据全错,单个 `a` 那组会打出 97 而不是 96,从 -1 起累加是题面点明的约定。
