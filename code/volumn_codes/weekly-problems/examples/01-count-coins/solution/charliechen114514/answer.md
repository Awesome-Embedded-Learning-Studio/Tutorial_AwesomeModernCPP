**思路**:Berkeley CS61A 经典题(略有改编)。以「当前可用的最小面值 `c`」分类:凑出 `total` 的方案数 = 至少用一枚 `c` 的方案数(递归 `total - c`,面值不变)+ 完全不用 `c` 的方案数(递归 `total`,换下一个面值)。边界:`total == 0` 恰好凑出,算 1 种;`total < 0` 或没有更大面值(`coin == 0`),算 0 种。

一个常见的坑:把 `coin == 25` 写进 `default: return 0`——那样递归里**永远用不上 25 美分**,`count_coins(100)` 会得到 121(等于只用 {1,5,10} 的方案数)而不是 242;而 `total < 25` 的测试全都照常通过,bug 藏得很深。

`count_coins(100) == 242` 是这道题的经典验收值。
